# Сверка с исходным заданием

Дата: 3 ноября 2026 года. Версия приложения: 0.11.1, проверяемая реализация — коммит `87f1757`.

Основания: [исходное задание](../Задание.txt), [вводная библиотеки](../Библиотека%20компонентов/Вводная%20информация.txt), исходный код и [история проверок](QA.md). Это сверка требований, а не новый полный браузерный прогон. В ходе сверки заново выполнен `npm.cmd run check`: каталог актуален, TypeScript проходит. Последний функциональный прогон реализации: 85 тестов и успешная production-сборка.

> Обновление 0.11.2: структура S/L нормализована по поручению пользователя — предметы перенесены в папки своих логических размеров, фоны сохранены. Статус `normalized` заменил инвертированное рабочее назначение; предупреждение `SIZE_MAPPING_ASSUMED` удалено. Ограничения одинаковой детализации остаются. См. [SIZE-MAPPING.md](SIZE-MAPPING.md). Таблицы ниже фиксируют состояние аудита 0.11.1.

## Итог

Основные функции конструктора реализованы. Сценарий по метафоре работает на описанных в словаре смыслах, но не является универсальным пониманием текста. Технического основания заявить «поддерживает любые метафоры» нет. В исходной библиотеке остаются документированные предположения о S/L и цветовых ролях. Комплект сдачи ещё требует короткой демонстрации и актуализации документов.

## Требования вводной библиотеки

| Требование | Статус и оговорка |
| --- | --- |
| Два размера отличаются детализацией | Выбор и подстановка работают. Для части исходных предметов различающаяся упрощённая геометрия отсутствует или не подтверждена; конструктор не изменяет контуры ради искусственной разницы |
| Три схемы с возможностью добавления | Выполнено. Дополнительная схема проверена тестом изолированной сборки; пользовательские палитры загружаются без новых SVG |
| Главные цветные, фоновые монохромные предметы | Стандартная библиотека имеет отдельные исходные варианты. Роль можно менять. Для своих SVG в дополнительном режиме доступны отдельные карты цветов и монохром по яркости; неназначенные цвета сохраняются исходными |
| Фоновые предметы необязательны | Выполнено. Автоматические дополнения включаются отдельно, состав и роли редактируются вручную |
| Цвета фонов допустимы в предметах, акценты предметов запрещены в фонах | Выполнено механизмом цветовых ролей: `paintSubstitutions` проверяет допустимые цели. Для явно настроенного фонового варианта своего SVG запрещены роли `object.*` |

Форматы квадрат 1000×1000, горизонтальный 1200×630 и вертикальный 800×1200 реализованы отдельно от S/L. ТЗ требует разные форматы, но не задаёт именно эти численные размеры. S/L отвечает за детализацию, а не разрешение холста.

## Что остаётся условным

1. **Авторское назначение S/L.** Пользователь ранее предупредил о возможной путанице названий. Сейчас логический S использует предметы из исходной папки L, логический L — из S, фоны сохраняют свои папки. Статус `working-assumption` открыт в каталоге. Перед сдачей нужно либо согласовать назначение, либо явно описать это предположение; молча объявлять его подтверждённым нельзя.
2. **Четыре предупреждения материалов.** `SIZE_MAPPING_ASSUMED`, `SECONDARY_NOT_SIMPLIFIED`, `NO_DISTINCT_DETAIL_PAIR`, `COLOR_ROLES_INFERRED` остаются в `library/validation-report.json`. Это не ошибки запуска, но ограничения исходников и классификации.
3. **Формулировка про 20 иллюстраций.** В реализации 10 типов предметов с вариантами, а не 20 разных типов. Число 20 в задании не означает обязанность придумать ещё 10 предметов. Каталог прослеживается к предоставленным компонентам; отдельная сверка каждого из 20 исходных макетов с каталогом в этой проверке не выполнена.
4. **Смысловой подбор.** Правила и тесты подтверждают поддерживаемые связи, но не гарантируют подходящую композицию для произвольной фразы. Последний замер 49/63 выполнен на знакомом авторском наборе и не является независимой точностью.
5. **Дополнительные свои SVG.** Импорт ограничен автономным статическим вектором; CSS-таблицы, растр, внешние ссылки и скрипты отклоняются. У своего SVG общая геометрия S/L. Эти дополнительные возможности не нужно выдавать за обязательные требования к исходной библиотеке.

## Приоритет перед сдачей

1. Зафиксировать и честно описать предположение S/L и ограничения подбора.
2. Обновить документы сдачи и архитектуры под 0.11.1: сейчас `DELIVERY.md` ещё упоминает удалённую модель, а README местами перечисляет старые 34 проверки. Для PowerShell указать рабочие команды `npm.cmd ci`, `npm.cmd run dev`.
3. Подготовить короткий показ обоих сценариев автоматической сборки, ручной правки, палитры, S/L и редактируемого SVG.

Новых крупных функций для закрытия перечисленных требований не выявлено. Дальнейшие изменения следует направить на устранение подтверждённых ошибок, оговорки материалов и комплект сдачи.

# Архитектура «Состава»

## Текущая версия

Приложение — статический React/TypeScript-клиент, собираемый Vite. Сервер, учётные записи, внешние API и облачная база данных для ручного редактора не используются.

```text
Исходные SVG + source-map.json + palettes.json
                    ↓ build-library.mjs
public/library/catalog.json + неизменённые SVG-копии
                    ↓
React: библиотека → модель сцены → SVG-холст
                          ├→ localStorage / .sostav.json
                          └→ exportSvg() → отдельные SVG-группы
```

## Подготовка и хранение

`library/source-map.json` связывает стабильный идентификатор предмета с четырьмя исходниками: S/L × main/secondary. Он содержит названия, смысловые теги и примечания к материалам. Размеры назначены явно, с рабочим статусом соответствия. Исходные файлы не перемещаются.

`scripts/build-library.mjs` проверяет исходные SVG, соответствие цветам, целостность ссылок и размерных пар. Собранные файлы сохраняются под стабильными URL. Каталог содержит метаданные каждого файла и SHA-256. `library:check` выявляет отличия между настройками, оригиналами и собранной библиотекой без записи.

## Модель сцены

`src/editor/model.ts` описывает JSON-проект версии 1: имя, размер иллюстрации, формат результата, палитра, пользовательские палитры, видимость фона, общий масштаб и упорядоченный список экземпляров.

Каждый экземпляр содержит ссылку на предмет, уникальный ID, роль, нормализованные координаты центра и угол поворота. SVG-контуры не записываются в проект: при открытии они берутся из каталога. Такой формат переиспользует исходники и не позволяет проекту подменять их произвольными SVG.

Порядок элементов в массиве — порядок от нижнего слоя к верхнему. При смене S/L или роли выбирается соответствующий оригинал. Относительные размеры задаются исходными координатами; все предметы сцены используют один коэффициент масштаба. Нельзя независимо растягивать предметы по осям или менять их внутренние элементы.

## Цвета

`library/palettes.json` описывает роли цветов и встроенные схемы. Фоновые цвета разрешены в предметах, объектные акценты — только в предметах. Белый и цвет контуров фиксированы согласно рабочему правилу библиотеки.

У каждого SVG в каталоге есть соответствие его фактических цветов ролям. Функция `preparedSvg()` меняет только цветовые атрибуты, не геометрию. Пользовательский JSON проверяется на полноту ролей и фиксированные нейтральные цвета. Палитры сохраняются вместе с проектом.

## Холст и экспорт

`src/ui/App.tsx` строит настоящий SVG-холст. Исходник предмета остаётся вложенным SVG с оригинальным viewBox; внешняя группа задаёт перенос, поворот и общий масштаб. Выделение — отдельная часть интерфейса. Перетаскивание учитывает матрицу экранных координат SVG, поэтому работает при разных масштабах просмотра.

`src/editor/svg.ts` используется и холстом, и экспортом. При вставке каждого экземпляра префиксуются ID определений и ссылки на них. Дублирование предмета не создаёт конфликтов градиентов и обрезки. Экспорт содержит фон и отдельные группы с названиями/идентификаторами предметов, исходные контуры и определения. Рамки выделения и прочие элементы интерфейса в него не попадают. Растрового промежуточного шага нет.

Фоны покрывают формат пропорционально через `preserveAspectRatio="xMidYMid slice"`; их рисунок может обрезаться краями формата, геометрия не растягивается. За пределами холста предметы обрезаются границами результата.

## История и сохранение

Редактор хранит до 60 состояний для undo/redo. Перетаскивание создаёт одну запись при отпускании указателя. Для полей и ползунков каждое принятое изменение создаёт состояние. Локальное сохранение обновляется после короткой задержки; при недоступном хранилище интерфейс предлагает скачать проект. История отмены и текущее выделение не записываются в файл проекта.

JSON проекта проверяется перед импортом: версия, предметы, роли, форматы, палитры, уникальность ID и конечные числовые координаты. Ограничения: до 100 экземпляров, 50 пользовательских палитр и файл до 2 МБ. Эти ограничения защищают интерфейс от непреднамеренно тяжёлых проектов; загрузка произвольных SVG не входит в текущую версию.

## Проверки

16 автоматических тестов проверяют исходники, четвёртую палитру без новых SVG, выбор размеров/ролей, допустимые цвета, импорт проектов, историю, слои, экспорт трёх сцен, сохранность контуров, отсутствие растра и уникальность внутренних ссылок.

Браузерная проверка выполняется отдельно: взаимодействия с интерфейсом, скачивание реального файла, импорт проекта/палитры, перезагрузка и адаптивность. Открытие экспорта в Figma/Illustrator пока не проверялось.

## Дальнейшее развитие

Автокомпоновка будет возвращать такую же модель сцены. Смысловой подбор через сервер будет возвращать существующие идентификаторы предметов и роли, а не новые изображения. Это позволяет добавлять автоматизацию без замены редактора и экспортного механизма.

# Архитектура «Состава»

## Текущая версия

Приложение — статический React/TypeScript-клиент, собираемый Vite. Сервер, учётные записи, внешние API и облачная база данных для ручного редактора не используются.

```text
Исходные SVG + source-map.json + palettes.json
                    ↓ build-library.mjs
public/library/catalog.json + неизменённые SVG-копии
                    ↓
React: библиотека → модель сцены → SVG-холст
                          ├→ localStorage / .sostav.json
                          └→ exportSvg() → отдельные SVG-группы
```

## Подготовка и хранение

`library/source-map.json` связывает стабильный идентификатор предмета с четырьмя исходниками: S/L × main/secondary. Он содержит названия, смысловые теги и примечания к материалам. Размеры назначены явно, с рабочим статусом соответствия. Исходные файлы не перемещаются.

`scripts/build-library.mjs` проверяет исходные SVG, соответствие цветам, целостность ссылок и размерных пар. Собранные файлы сохраняются под стабильными URL. Каталог содержит метаданные каждого файла и SHA-256. `library:check` выявляет отличия между настройками, оригиналами и собранной библиотекой без записи.

## Модель сцены

`src/editor/model.ts` описывает JSON-проект версии 1: имя, размер иллюстрации, формат результата, палитра, пользовательские палитры, видимость фона, общий масштаб и упорядоченный список экземпляров.

Каждый экземпляр содержит ссылку на предмет, уникальный ID, роль, нормализованные координаты центра и угол поворота. SVG-контуры не записываются в проект: при открытии они берутся из каталога. Такой формат переиспользует исходники и не позволяет проекту подменять их произвольными SVG.

Порядок элементов в массиве — порядок от нижнего слоя к верхнему. При смене S/L или роли выбирается соответствующий оригинал. Относительные размеры задаются исходными координатами; все предметы сцены используют один коэффициент масштаба. Нельзя независимо растягивать предметы по осям или менять их внутренние элементы.

## Цвета

`library/palettes.json` описывает роли цветов и встроенные схемы. Фоновые цвета разрешены в предметах, объектные акценты — только в предметах. Белый и цвет контуров фиксированы согласно рабочему правилу библиотеки.

У каждого SVG в каталоге есть соответствие его фактических цветов ролям. Функция `preparedSvg()` меняет только цветовые атрибуты, не геометрию. Пользовательский JSON проверяется на полноту ролей и фиксированные нейтральные цвета. Палитры сохраняются вместе с проектом.

## Холст и экспорт

`src/ui/App.tsx` строит настоящий SVG-холст. Исходник предмета остаётся вложенным SVG с оригинальным viewBox; внешняя группа задаёт перенос, поворот и общий масштаб. Выделение — отдельная часть интерфейса. Перетаскивание учитывает матрицу экранных координат SVG, поэтому работает при разных масштабах просмотра.

`src/editor/svg.ts` используется и холстом, и экспортом. При вставке каждого экземпляра префиксуются ID определений и ссылки на них. Дублирование предмета не создаёт конфликтов градиентов и обрезки. Экспорт содержит фон и отдельные группы с названиями/идентификаторами предметов, исходные контуры и определения. Рамки выделения и прочие элементы интерфейса в него не попадают. Растрового промежуточного шага нет.

Фоны покрывают формат пропорционально через `preserveAspectRatio="xMidYMid slice"`; их рисунок может обрезаться краями формата, геометрия не растягивается. За пределами холста предметы обрезаются границами результата.

## История и сохранение

Редактор хранит до 60 состояний для undo/redo. Перетаскивание создаёт одну запись при отпускании указателя. Для полей и ползунков каждое принятое изменение создаёт состояние. Локальное сохранение обновляется после короткой задержки; при недоступном хранилище интерфейс предлагает скачать проект. История отмены и текущее выделение не записываются в файл проекта.

JSON проекта проверяется перед импортом: версия, предметы, роли, форматы, палитры, уникальность ID и конечные числовые координаты. Ограничения: до 100 экземпляров, 50 пользовательских палитр и файл до 2 МБ. Эти ограничения защищают интерфейс от непреднамеренно тяжёлых проектов; загрузка произвольных SVG не входит в текущую версию.

## Проверки

34 автоматических теста проверяют исходники, четвёртую палитру без новых SVG, выбор размеров/ролей, допустимые цвета, импорт проектов, историю, слои, экспорт, сохранность контуров, отсутствие растра, уникальность внутренних ссылок, автоматическую компоновку и локальный смысловой подбор.

Браузерная проверка выполняется отдельно: взаимодействия с интерфейсом, скачивание реального файла, импорт проекта/палитры, перезагрузка и адаптивность. Открытие экспорта в Figma/Illustrator пока не проверялось.

## Автоматическая компоновка

`src/editor/layout.ts` — детерминированный алгоритм без внешних API. Вход — обычная модель сцены и настройки дополнений. Состав экземпляров и выбранные роли сохраняются; для новых запросов `parseObjectNames()` распознаёт только имена и явные синонимы существующих предметов. Неизвестные слова блокируют сборку. Повторяющиеся имена создают отдельные экземпляры.

Алгоритм оценивает габариты исходных viewBox после поворота. Он перебирает порядок предметов и разбиение на ряды, а для небольших диагональных сцен — цепочки предметов. Позиции рассчитываются в исходных координатах, затем вся группа равномерно вписывается в формат с отступом 6,5%. Размеры отдельных предметов независимо не нормализуются.

Для каждой из трёх композиционных схем кандидаты проверяются на выход за границы и перекрытие повёрнутых ограничивающих прямоугольников. Перекрытие ограничено 28% площади меньшего прямоугольника. Оценка учитывает заполнение холста и отличие расположения от предыдущих вариантов. Это консервативная проверка прямоугольников, а не пиксельных контуров. Все предметы сохраняют свои SVG; геометрия не генерируется и не упрощается.

Фоновые экземпляры отрисовываются перед главными. Если пользователь разрешил дополнение, один новый фоновый предмет выбирается из явных связей между существующими предметами. Общее число — максимум шесть. Никакие исходные экземпляры не отбрасываются для прохождения лимита; чрезмерный запрос отклоняется с объяснением. Сцены, состоящие только из фоновых предметов, отклоняются.

`AutoComposeDialog.tsx` показывает три векторных превью и позволяет выбрать вариант. Превью используют отдельные пространства имён SVG-идентификаторов. До применения базовая сцена не меняется; изменение настроек делает старые варианты неприменимыми. Применение — один коммит в локальной истории редактора. Seed позволяет воспроизвести результат и получить новые варианты.

8 тестов компоновки проверяют имена и ошибки, воспроизводимость, разные форматы/размеры и 1–6 предметов, дубликаты, единственный предмет, фоновые дополнения, экспорт исходных контуров, уникальность определений и undo.

## Локальный смысловой подбор

По выбору пользователя версия 0.4.0 не использует API-ключи. `src/editor/meaning.ts` содержит 18 тем, набор корней и устойчивых выражений, а также взвешенные связи с предметами и готовые объяснения. Это обозримая онтология и ранжирование, не обученная модель. Ввод и библиотека не отправляются во внешние сервисы.

Сначала выделяются простые отрицательные фрагменты, ограниченные пунктуацией/противопоставлением. Указанные в них предметы и основные предметы отрицательных тем исключаются. Поэтому «без телефона» удаляет телефон, а «безопасность» не трактуется как отрицание. Затем сопоставляются положительные слова и выражения. Явные упоминания предметов имеют приоритет; тематические веса определяют главные предметы с покрытием разных тем (до трёх, кроме явно перечисленных предметов). По разрешению пользователя добавляется один второстепенный фоновый предмет.

Результат `MeaningResult` возвращает только ID предметов текущего каталога, роли, причины, распознанные понятия и ограничения. Частичность — эвристика покрытия значимых слов словарём, а не статистическая вероятность. При отсутствии надёжной связи возвращается `unmatched` без предметов; предыдущие варианты очищаются, применение блокируется. Сложные отрицания, сарказм и неизвестные метафоры не покрываются универсально.

`objectsFromMeaning()` проверяет контракт и превращает подбор в экземпляры. Они передаются в существующий `generateLayouts()`; контуры и координатная система остаются теми же. Дополнительные предметы не добавляются повторно алгоритмом компоновки: для смыслового режима их выбирает слой подбора.

В сцену добавлено необязательное поле `interpretation`, совместимое со старыми JSON-проектами. Оно сохраняет исходную причину подбора, не пересчитывается после каждой ручной правки и проверяется при импорте. При применении нового подбора по названиям/холсту прежняя интерпретация удаляется. После ввода новой темы прежние пользовательские переопределения её ролей сбрасываются; изменение роли уже полученного подбора остаётся явным действием пользователя.

10 тестов смыслового подбора проверяют тематические и метафорические запросы, исключения и границы фраз, неизвестные/частичные темы, ограниченный каталог, фоновые роли, валидацию происхождения подбора и полный путь до SVG и JSON во всех форматах и размерах. Всего 34 теста.

## Дальнейшее развитие

При необходимости универсального понимания можно добавить отдельный серверный адаптер модели с проверкой того же контракта `MeaningResult`. Ключ не должен попадать в клиентскую сборку. В текущую версию этот адаптер не включён, живые запросы к модели не выполнялись. Дальнейшая работа для сдачи: визуальная оценка тем, проверка экспорта в векторном редакторе, публикация и демонстрация.
